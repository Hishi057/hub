## **Everything is a file**  
UNIXの設計思想。
あらゆるものをファイルとして共通した規格で統一することで、基本的な操作で扱えるようになる。例えばディレクトリ、デバイスファイル、標準入出力なども"ファイル"である。

## デバイスファイル

`struct file`のフィールド`type`として`FD_DEVICE`が指定されたファイルのこと。
通常のファイルと異なり、外部装置の[入出力](input_output_port.md)のために用いられる。

### console

`console`ファイルとは、デバイスファイルの一種である。このファイルに書き込むとターミナルに表示されて、consoleを読み込むとキーボードから入力した文字が取得できる。

xv6において、最初のユーザプログラム`init`において次のような処理が必ず実行されることで
標準入力、標準出力、エラー出力が`console`と結びつく。

```c
// consoleファイルの作成
if (open("console", O_RDWR) < 0){
    mknod("console", CONSOLE, 0);
    open("console", O_RDWR);
}

dup(0); // fd 1 がconsoleに繋がる
dup(0); // fd 2 がconsoleに繋がる
```

## inode

ファイルのメタデータ(所有者、ハードリンク数など)を記録したデータ構造のこと。
また、中身のデータそのものがどこに保存されているかも記録している。

### (xv6上における) dinode

(前提知識) xv6において、ディスク上の1ブロックは1024バイトを指す。

**dinode(disc inode)** とは、ディスク上の構造体である。ディスク内のinodeブロックに存在する。1つのファイルあたり1つのdinodeが対応することで、ファイルの情報を管理している。  
dinodeは1つ64バイトであるから、1inodeブロックあたり$1024/64=16$つのdinodeが作れる。  

dinodeは特に、13個の要素からなる配列**addrs**を持っていて、データブロック番号(つまり中身のデータが保管されている場所)
を保存している。

**addrs**  
`addrs[0]`~`addrs[11]`: 直接データブロック番号を指している。  
`addrs[12]`: 最大256個のブロック番号を格納した**間接参照ブロック**を指している。  
(`addrs`は1要素あたり4バイトなので、間接参照ブロックは$1024/4=256$個データブロック番号を指す領域を保有できる。)  

### inode と dinode と file の違い。

**dinode**: ディスク上に記録される構造体。ただし"inodeブロック"はディスク上に存在する。  
**inode**: メモリ上に記録される構造体。必要に応じてディスクからdinodeを取り出して、追加情報も記録した構造体。  
**file**: 現在開いているファイルの状態を管理する構造体。`off`:現在の読み書き位置, `pipe`:パイプを指すポインタなどのフィールドを持っている。
